## A query, not a download

You get a hostname, a user and a password. That's the entire onboarding.

The ten most prolific Pump.fun creators of the last 30 days, and how much of
each token's supply they bought into their own launch:

```sql
SELECT
    creator,
    count()                                                       AS launches,
    round(avg(bundled_buys_count), 1)                             AS avg_bundled_buys,
    round(avg(bundled_buys / if(mayhem_mode = 1, 2e13, 1e13)), 1) AS avg_bundle_pct_supply,
    toTimeZone(max(block_time), 'UTC')                            AS last_launch_utc
FROM pumpfun_token_creation
WHERE block_time > now() - INTERVAL 30 DAY
GROUP BY creator
ORDER BY launches DESC
LIMIT 10
```

## Why this is hard to get elsewhere

### Depth

Pump.fun activity back to January 2024, across launches, bonding-curve trades,
migrations and creator fees. Nothing sampled, nothing rolled up into hourly
candles before it reaches you.

### Resolution

Every swap carries the execution context you need to model it properly: pool
reserves before and after, priority fees and compute units, the parent program
that invoked the instruction, the fee payer, and slippage against the requested
amount. Most providers hand you a price and a size.

### Direct access

It's a ClickHouse database, not an API. Run a full table scan. Pull two years of
swaps into a dataframe. JOIN across tables. Aggregate server-side and take back
only the result. No rate limits, no row caps, no credits, no pagination. If a
query gets heavy, we help you make it faster — we don't throttle you.
